* Problem 62 :binary_search_tree:lower_bound:sorting:
** Task
#+begin_quote
Argue that since sorting $n$ elements takes $\Omega(n \lg n)$ time in the worst case in the comparison model, any comparison-based algorithm for constructing a binary search tree from an arbitrary list of $n$ elements takes $\Omega(n \lg n)$ time in the worst case.
#+end_quote

** Solution

In-order traversal of a binary search tree on $n$ elements yields the elements in sorted order in $O(n)$ time using *no key comparisons* — only pointer-following: =INORDER-TREE-WALK= branches solely on the nil-check $x \neq \text{NIL}$, never on $x.key$ (CLRS treats inorder order as determined by tree structure alone, §12.2).

So if a comparison-based algorithm builds a BST in $T(n)$ time, then "build, then traverse in-order" is a comparison-based sort running in $T(n) + O(n)$. Comparison sorting is $\Omega(n \lg n)$, hence

$$T(n) + O(n) = \Omega(n \lg n) \;\Longrightarrow\; T(n) = \Omega(n \lg n)$$

#+end_quote

** Solution

#+begin_src julia :results output
using Test

mutable struct Node{T}
    data::T
    left::Union{Node{T}, Nothing}
    right::Union{Node{T}, Nothing}
    parent::Union{Node{T}, Nothing}
end

function Node(data::T, left::Union{Node{T}, Nothing}=nothing, right::Union{Node{T}, Nothing}=nothing) where T
    node = Node{T}(data, left, right, nothing)
    (left !== nothing) && (left.parent = node)
    (right !== nothing) && (right.parent = node)
    return node
end

mutable struct BinaryTree{T}
    root::Union{Node{T}, Nothing}
    BinaryTree{T}() where T = new(nothing)
end

function tree_maximum(x::Node)
    while x.right !== nothing
        x = x.right
    end
    return x
end

function tree_predecessor(n::Node{T}) where T
    if n.left !== nothing
        return tree_maximum(n.left)
    end
    y = n.parent
    while y !== nothing && n === y.left
        n = y
        y = y.parent
    end
    return y
end

@testset "tree_predecessor" begin
    #      4
    #     / \
    #    2   5
    #   / \
    #  1   3
    n1 = Node(1)
    n3 = Node(3)
    n5 = Node(5)
    n2 = Node(2, n1, n3)
    n4 = Node(4, n2, n5)

    @test tree_predecessor(n5) === n4
    @test tree_predecessor(n4) === n3
    @test tree_predecessor(n3) === n2
    @test tree_predecessor(n2) === n1
    @test tree_predecessor(n1) === nothing
end

* Problem 64 :binary_search_tree:counterexample:
** Task
#+begin_quote
Professor Kilmer claims to have discovered a remarkable property of binary search trees. Suppose that the search for key $k$ in a binary search tree ends up at a leaf. Consider three sets: $A$, the keys to the left of the search path; $B$, the keys on the search path; and $C$, the keys to the right of the search path. Professor Kilmer claims that any three keys $a \in A$, $b \in B$, and $c \in C$ must satisfy $a \leq b \leq c$. Give a smallest possible counterexample to the professor's claim.
#+end_quote

** Solution

Search for any key $k > 3$ in the following BST:

#+begin_example
    1
     \
      3
     /
    2
#+end_example

- $B$ (Keys on path): $\{1, 3\}$
- $A$ (Keys left of path): $\{2\}$
- $C$ (Keys right of path): $\emptyset$

The claim asserts $a \leq b$ for all $a \in A$ and $b \in B$. Choosing $a = 2 \in A$ and $b = 1 \in B$ yields $2 \not\leq 1$. Therefore, the claim is false.

* Problem 65 :binary_search_tree:predecessor:successor:
** Task
#+begin_quote
Let $T$ be a binary search tree whose keys are distinct, let $x$ be a leaf node, and let $y$ be its parent. Show that $y.key$ is either the smallest key in $T$ larger than $x.key$ or the largest key in $T$ smaller than $x.key$.
#+end_quote

** Solution

$x$ is a child of $y$, so it is either the left or right child.

- Case 1: $\mathrm{left}(y) = x$.

  By the BST property, $x.key < y.key$.

  Suppose some $z$ has $x.key < z.key < y.key$.
  - $z.key < y.key \Rightarrow z$ is in $y$'s left subtree.
  - $z.key > x.key \Rightarrow z$ is in $x$'s right subtree.

  But $x$ is a leaf, so it has no right subtree. Contradiction. Hence $y.key$ is the smallest key larger than $x.key$.

- Case 2: $\mathrm{right}(y) = x$.

  By the BST property, $x.key > y.key$.

  Suppose some $z$ has $y.key < z.key < x.key$.
  - $z.key > y.key \Rightarrow z$ is in $y$'s right subtree.
  - $z.key < x.key \Rightarrow z$ is in $x$'s left subtree.

  But $x$ is a leaf, so it has no left subtree. Contradiction. Hence $y.key$ is the largest key smaller than $x.key$. $\qed$
