* Purpose

Single source of truth for directory layout and file naming in this repository.

- =tree.org= is a generated snapshot — the territory, not the rules.
- This file records *what* the structure is *now* (the spec).
- =00_global/prompts/= holds task instructions for LLM-assisted work; it
  references this file for naming and must not restate it.

When this file and =scripts/validate_structure.py= disagree, one of them is
wrong — fix it. They must not drift.

* Naming rules — apply everywhere

- Lowercase =snake_case=. ASCII only.
- No spaces, no =&=, no quotes. Every name must survive shell globbing unquoted.
- Numeric prefixes (=NN_=) pin sort order. They denote *parallel categories*,
  not a sequence — =01_material= is not "before" =02_problems= in any real sense.
- Zero-pad numbers to width two: =ps_01=, =lecture_07=, =p_03.png= — never
  =ps_1= or =p_9.png=.
- Leading =_= marks non-content: machinery directories and raw upstream files.
  It sorts them to the top.
- The =_source= suffix marks upstream, unedited input: =analysis_source.pdf=,
  =ps_01_source.pdf=.

* 01_coursework/

Layout:

#+begin_example
01_coursework/NN_semester/NN_course/<facet>/
#+end_example

Semesters are =NN_semester=. Courses are =NN_course=
(=00_steop=, =01_analysis=, =02_linear_algebra=, ...).

** Course facets — the contract

Every course directory contains exactly these facets:

- =01_material/= — required
- =02_problems/= — required
- =03_exams/=    — present once the course has had exams

No other directories at the course level.

** 01_material/

Flat. *No subdirectories.*

- =ch_NN_slug.org=  — chapter-aligned notes, or
- =slug.org=        — topic-aligned notes (e.g. =induction.org=)
- =theorems.org=    — consolidated theorem index, if the course warrants one
- =_<subject>_source.pdf= — the single upstream source document

The semester-2 shape is canonical. The =lecture_org/= + =lecture_pdf/= format
split and the =lecture_notes/= nesting are *deprecated* — retrofit older
courses to the flat shape.

** 02_problems/

One directory per problem set:

#+begin_example
02_problems/ps_NN/
    ps_NN.org           worked solutions (required)
    ps_NN_source.pdf    the original problem sheet
    ps_NN.ipynb         code — only when a problem needs it
    assets/             images used by ps_NN.org; named p_NN[_x].png
#+end_example

Every problem set is a =ps_NN/= directory, even if it would hold a single
file — the uniform shape is the point.

** 03_exams/   [PROVISIONAL — ratify once all semester-2 courses conform; algorithms is still on the pre-split layout]

Five stage-numbered slots. The number encodes the *role*, not sequence
position: unused stages are simply absent and the rest do NOT renumber
(cf. semester-1 STEOP =01_lecture_exam/= runs 00→01→02→04, no 03).
Typical minimum populated is 00→01→02.

#+begin_example
03_exams/
    00_resources/     irreplaceable INPUTS — cannot be regenerated
        notes/          notes_<name>.{org,jpeg}   own + crowdsourced; distilled recording intel
        transcripts/    lec_NN.txt                machine transcripts (see Recordings)
    01_extracted/     LLM BUILD PRODUCTS — disposable, regenerable from 00_ + rules
        material.org    synthesis spine; + course-dependent:
                          theorems.org                       proof-heavy course
                          problems.org                       computation-heavy course
                          <paper>.org / <paper>_solution.org past-paper course
    02_plan/          plan.org               preparation plan, built from 01_
    03_preparation/   day_NN.org, assets/    worked preparation
    04_revision/      cheatsheet.org         final condensed pass (optional)
#+end_example

*Core invariant.* =00_resources/= (sources) and =01_extracted/= (products) are
never conflated. Test: =rm -rf 01_extracted/ && regenerate= must be obviously
safe. If deleting a file loses information you cannot reproduce, it belongs in
=00_resources/=, not =01_extracted/=.

*Multiple distinct exams* → split one level up, each a full stack:
=03_exams/0N_<exam_name>/{00_resources,…}= (STEOP: =01_lecture_exam/=,
=02_exercise_exam/=).

*Recordings.* Audio (=.m4a=/=.mp3=) is transient and NOT committed;
=00_global/scripts/{m4a,mp3}_to_txt.py= converts it to =lec_NN.txt= in
=transcripts/=. The "professor previews the exam" case: transcribe, then distil
the exam-relevant part into a =notes/= file. Recordings enter the pipeline as
transcripts (machine) or notes (curated) — never as raw audio.

*Raw / irreplaceable captures* are marked by a =_source= filename suffix in
place, not a =_raw/= dir: =page_NN_source.jpeg=, =ps_NN_source.pdf=. (Leading-
underscore material PDFs =_<course>_source_NN_semester.pdf= are the unresolved
repo-wide =_= question — out of scope here.)

*Reproducibility header — required on every =01_extracted/= file.* The layout
makes products disposable; it does NOT make them deterministic. Pin the
transform in the file:

#+begin_src org
#+model:  claude-opus-4-8
#+prompt: 00_global/prompts/03_exams/course_specific/<course>/<rule>.org@<sha>
#+date:   2026-07-09
#+end_src

Rules live centrally under =00_global/prompts/03_exams/= (=00_general= +
=01_course_specific/<course>=), not inside the exam folder — this header is the
only pointer from a product back to the exact rule + model that produced it.

* Source vs derived files   [DECIDE]

- =.org= and =.ipynb= are *source* — always tracked.
- =_source.*= files are upstream input — always tracked.
- =X.pdf= exported from =X.org= is *derived*. Recommendation: gitignore it and
  rebuild on demand. If you instead choose to commit exports, commit them for
  *every* =.org= — no partial coverage, which is the current inconsistent state.

* Enforcement

=scripts/validate_structure.py= checks the rules above. This file is the
human-readable spec; the validator is the executable one. A change to the
convention is not done until both are updated.
